house-style · templates/sks-blue

One blue, two fields

The product-facing template — and the only one in the system that ships two fields. A white page and a near-black page, sharing one accent, one grid, one type scale and one chart ramp. Read from the SPACES prototype, which does exactly this: a dark hero, then light sections, with the same blue running through both.

Light field#FFFFFF · panel #F1F4FC · callout #E5E9F6
Dark field#080D1A · panel #101832 · callout #16204A
The hex values are read, not sampled

Every other palette in this system was measured — pixels sampled out of a source deck or a comp. These were read off the SPACES prototype by eye, because the Figma file is not shared with the account wired into this toolchain and the prototype renders to a WebGL canvas whose buffer cannot be read back. Expect each channel within a few points of the brand's real value.

The ratios on this page are exact: they are computed from the hexes as written. Correct a hex, re-run the contrast script, and every number follows.

One blue, three values

The spine of the palette is a single hue at three values. The only thing that changes between the two themes is which of the three carries type — which is why the three divider layouts are identical in both files, and only the content pages flip.

Chart ramp — shared by both themes

A series must not change hue when a deck is restyled, so the eight categorical colours are pitched at one luminance and clear ≥ 3.5:1 on all six surfaces — three light tints and three dark. The cost is that none of them is text-safe in either theme: a single hue cannot be legible against both white and near-black. Set series labels in ink or muted ink and let a legend swatch carry the colour.

Series 1 is #3D6AFF, not the accent. #2F55F0 falls to 2.75:1 on the dark callout tint and would disappear inside a callout band. The ramp's blue is one value step up and holds everywhere. There is no approved alert colour — orange and rose here are categorical hues, not status marks.

02

Type

Arial for Latin, 微軟正黑體 for 中文, in every template and both themes. Bold is the only weight variation — no italics, no letter-spacing tricks, no all-caps runs longer than three words. Sizes below are on the 1440 × 810 pt canvas; on a conventional 960pt canvas they are two-thirds of these numbers. The upstream pptx skill's ≥36pt title rule assumes a projected deck and does not apply here.

On the dark file, do not add bold to body copy to compensate for the ground. Light type on dark blooms — strokes read heavier than they measure. If a line is not reading, it is a colour problem, not a weight problem.

03

Components

Every mark below is drawn from the tokens above, and nothing changes shape between the themes — only which token each part reaches for. A component that sets a blue label uses --accent-text; one that sets a blue area uses --accent. Reaching for --accent as a text colour passes in light and fails in dark.

Buttons

Primary is a #2F55F0 fill with white text — 5.71:1 in both themes. Never dark ink on it (3.17:1).

The gate4.5:1 below 24px, 3.0:1 at or above. Every ratio here is computed from the hex, never estimated — scripts/contrast.py --check verifies the tokens against both .pptx files.

Two files, one identitysks-blue.pptx and sks-blue-dark.pptx carry the same nineteen layouts on the same 1440 × 810 pt grid. Switching between them is a master swap, not a rebuild.

Never mix templatesANA Blue is the corporate register — board, regulator, investor. SKS Blue is the product register. Different fields, different accents; the mixture reads as a mistake.
